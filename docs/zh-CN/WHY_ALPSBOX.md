# 为什么做 ALPSbox？

[English](../WHY_ALPSBOX.md) | [简体中文](WHY_ALPSBOX.md)

**一句话回答**：数值上，ALPSbox 与参考实现的差异在 eddy 噪声范围内
（参数对齐时同一被试差 0.70%；30 例外部被试 r = 0.994）。区别在**研究流程**：
参考实现是一次一个被试的命令行脚本；ALPSbox 补上了经过验证的批处理、质控、
可打印报告，以及每个被试的处理口径记录。

---

## 1. 数值一致性

DTI-ALPS 最广泛使用的开源参考实现是
[gbarisano/alps](https://github.com/gbarisano/alps)（`alps.sh`，MIT，commit
`e6f58e7`）。参数对齐后（参考脚本需要 `-d 3 -e eddy_cuda11.0 -r 2.5 -t 1 -f 2`
再加一个 `normmi` 代价补丁；它的默认设置不同，见
[CITATIONS.md](CITATIONS.md) §2.1），确定性中间结果完全一致（去振铃 DWI、脑掩膜、
ROI 掩膜与体素数、公式），且 30 例完全外部被试上逐被试一致性为 r = 0.994
（ICC 0.994，平均绝对差异 1.52%）——在 eddy 自身 2.04% 的重复运行噪声之内。
这说明它是既有的 DTI-ALPS 指数，不是新算法；细节与全部参数见
[VALIDATION.md](VALIDATION.md) §1。

## 2. ALPSbox 多了什么

| 维度 | ALPSbox | 参考实现 |
|---|---|---|
| 带自动输入发现的图形界面 | 有 | 无 |
| 一条命令跑完整队列、可中断续跑 | 有 | 无（一次一个被试） |
| 8 类质控（分档 + 可操作建议） | 有 | 无 |
| **配准稳健性质控（`--regqc`）** | **有** | 无 |
| 一键生成人类可读的 HTML 报告（可打印为 PDF） | 有 | 无（只有 CSV） |
| 每条结果记录处理口径 | 有 | 无 |
| 中英文 GUI / CLI / HTML 报告 | 有 | 无 |
| 默认流程用 `vecreg` 做张量重定向 | 有 | 无（默认 `-f 1`） |
| 去噪 / TOPUP | 有 | 有 |
| 组统计 | **无（刻意不做）** | 无 |

关于默认张量路径：扩散张量在空间之间变换时必须按 `T' = R·T·Rᵀ` 重定向
（Alexander et al. 2001）；Tatekawa et al. 2023 报告重定向可改善可重复性。
因此 ALPSbox 默认用 `vecreg`，而参考脚本默认是 `-f 1`（不重定向）；参考脚本
加 `-f 2` 时做的是同一件事。这是处理口径上的差异，不代表哪个工具"更正确"——
发表时写明所用口径即可。

## 3. 可复现性本身就是功能

对研究来说，重要的不只是 ALPS 数值，而是知道它是怎么算出来的。每个被试的
`alps_result.json` 与 HTML 报告都会记录实际处理口径（`bet_f`、配准代价、模板、
去振铃、去噪、eddy 方法、ROI 体素数、全部质控值）；队列跑完后可以只重新汇总
或重新出报告，不必重跑处理。验证数值与每个验证实验的参数见
[VALIDATION.md](VALIDATION.md)。

## 4. ALPSbox 刻意不做什么

- 不做组间比较或前后测统计。导出每个被试的 CSV/JSON，用统计软件完成；
  保持工具专注正是目的。
- 不声称是官方或标准实现——ALPS 并没有这种标准。术语与引用见
  [CITATIONS.md](CITATIONS.md)。
- 不替代 FSL/MRtrix3，只负责调度它们并检查结果。

## 5. 什么时候参考实现可能更合适

- 只处理单个被试、不想装 Python 包，且习惯直接改 shell 参数。
- 需要参考脚本的精确默认口径（`-f 1`、去噪 + 去振铃、`corratio`）做直接复现。
- 只需要一个含 ALPS 数值的 CSV，其它都不需要。

这些情况直接用 `alps.sh` 就好。ALPSbox 面向的是跑队列、检查数据质量、
保留可报告的处理记录。
