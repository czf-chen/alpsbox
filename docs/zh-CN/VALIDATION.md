# 验证摘要

[English](../VALIDATION.md) | [简体中文](VALIDATION.md)

本页按我们提出问题的顺序讲验证故事：

1. **ALPSbox 的数值与参考实现是同一个测量吗？**
2. **到底什么会改变 ALPS？哪些因素最重要？**
3. **质控是否提供了有用信息？**

全部实验参数见 §5。外部验证队列是公开数据（OpenNeuro `ds000030`）；内部队列
因被试隐私不再分发，但逐实验完整记录可向作者索取。

---

## 1. 与参考实现是同一个测量

**结论：ALPSbox 计算的是既有的 DTI-ALPS 指数，不是新算法。**

- 确定性环节与参数对齐后的参考实现（`gbarisano/alps`，MIT）逐项一致：
  去振铃后 DWI 的 md5、脑掩膜体素数、ROI 掩膜（每个 81 体素）、ROI 质心，
  以及公式 `mean(Dxx_proj, Dxx_asso) / mean(Dyy_proj, Dzz_asso)`。
- 在**完全外部的 OpenNeuro ds000030 的 30 例健康对照**上，处理参数对齐
  （参考脚本用 `-d 3 -e eddy_cuda11.0 -r 2.5 -t 1 -f 2`，配准代价 patch 为
  `normmi`）：Pearson **r = 0.994**、**ICC = 0.994**、平均绝对差异 **1.52%**，
  30 例全部在 5% 以内。
- 同一输入重复跑 eddy 的波动为 **2.04%**（重复运行最大 4.11%），因此跨实现
  一致性已达到测量噪声下限；同被试参数对齐对比的 0.70% 差异也在噪声内。

**结论**：数值是同一个测量；与参考实现的差异来自处理设置，而不是公式不同。

---

## 2. 什么会改变 ALPS——按重要性排序

ALPS 是配准后扩散张量分量的比值，任何改变张量、掩膜或配准的选择都会改变数值。
在我们的实验中，实际重要性排序为：

| # | 因素 | 实验 | 对 ALPS 的观测影响 |
|---|---|---|---|
| 1 | **配准路径**（直接 FA→模板 vs 两步复合变换） | 配对，10 例对照 | \|ΔALPS\| 中位数 **16%**；10/10 例配准质量变差 |
| 2 | **脑提取阈值** `bet -f` 0.5 vs 0.3 | 24 例对照；15 例外部队列复现 | 平均 **11.2%**，中位 6.7%，最大 **43.9%**；复现：低 `r_wm` 组中位 5.8% vs 1.3% |
| 3 | **配准矩阵的微小误差**（`--regqc` 指标） | 24 例对照，12 次 ±0.5° / ±0.5 mm 扰动 | ALPS 极差 **6.6–12.0%** |
| 4 | **配准代价函数** `normmi` vs `corratio` | 5 例外部被试 | 平均 \|ΔALPS\| **5.9%**，最大 14.1% |
| 5 | **TOPUP 畸变校正** 开 vs 关 | 1 例真实 PA/AP 数据 | **−4.43%**（单例，只说明方向，不能外推幅度） |
| 6 | **eddy 非确定性**（同一输入重复运行） | 3 例内部对照 | **2.04%**（最大 4.11%）——噪声下限 |

从上往下读就是实际结论：**配准相关选择影响最大，其次是脑提取阈值；eddy 重复
运行的噪声最小，它决定了多大的差异才值得解释。**

这正是 ALPSbox 在每个 `alps_result.json`/报告中记录完整处理口径、并提供配准
稳健性质控（`--regqc`）的原因：只有处理口径固定且被报告，ALPS 数值才可比。

## 3. 质控有用吗？

**结论：质控能识别出"数值不宜直接采信"的被试。**

- 配准质量（`r_wm`，FA 与模板的相关系数）可以预测 ALPS 对预处理的敏感度：
  在 15 例外部复现中，改变 `bet` 阈值使低 `r_wm` 组的 ALPS 中位变化 **5.8%**，
  高 `r_wm` 组仅 **1.3%**；相关系数 **r = −0.69**，控制头动后的偏相关为
  **−0.77**。
- `--regqc` 直接量化每个被试对配准的敏感度：若某被试在 ±0.5° / ±0.5 mm 扰动下
  ALPS 变化 6–12%，那么无论其 ALPS 数值多少，都不足以支撑精细的个体间比较。
- 八类质控（配准质量、帧间运动、绝对漂移、离群切片、校正方法、ROI 体素数、
  ALPS 合理性、配准稳健性；处理状态单独报告）把这些诊断变成通过/提示/需注意/
  不合格分档，并给出可操作建议，可以快速筛查整个队列。

**结论**：质控不是装饰，它标出的是"会改变答案"的被试和设置。

---

## 4. 对使用者的意义

- 同一研究内固定一套处理口径并报告它——ALPSbox 的每个结果文件都记录了该口径。
- 所有被试的 `bet -f`、配准代价与模板保持一致，并写进方法部分。
- 用 `--regqc`（至少用 `r_wm`）识别对配准敏感的被试；未经重新验证，不要跨处理
  口径或跨采集协议直接比较 ALPS。
- 纯复现参考实现的结果时，直接用参考脚本更合适；ALPSbox 的价值是让同一个测量
  能实际用于队列（见 [WHY_ALPSBOX.md](WHY_ALPSBOX.md)）。

## 5. 实验参数

除特别说明外，所有实验使用 ALPSbox 默认处理口径：

| 项目 | 设置 |
|---|---|
| 数据 | 3T、单壳 DTI，b = 1000 s/mm² |
| 内部队列 | 1.5 mm 各向同性、64 方向，健康对照 |
| 外部队列 | OpenNeuro **ds000030**，面内 1.98 mm，健康对照 |
| 输入 | NIfTI DWI + bval/bvec + BIDS JSON sidecar |
| 畸变/头动校正 | FSL `eddy`（CUDA 版）加 `--repol` |
| Gibbs 去振铃 | MRtrix3 `mrdegibbs`；去噪（`dwidenoise`）关闭 |
| 脑提取 | `bet -f 0.5`（FSL 与参考实现默认值） |
| 张量拟合 | `dtifit --save_tensor`（单张量） |
| FA → 模板配准 | FLIRT 12 DOF，代价 `normmi`，模板 `JHU-ICBM-FA-1mm` |
| 张量重定向 | `vecreg`（`T' = R·T·Rᵀ`） |
| ROI 定义 | 随包 2.5 mm 半径球（每个 81 体素） |
| 软件 | ALPSbox 1.0.0、FSL 6.0.x、MRtrix3（当时最新版） |

工具写出的每个 `alps_result.json` 都记录该被试实际使用的处理口径
（`bet_f`、`reg_cost`、`template`、`unring`、`denoise`、eddy `method`），
因此参数表可直接从输出文件重建。

| 实验 | n | 数据 | 与默认口径的差异 |
|---|---|---|---|
| 参考实现对比（参数对齐、同一被试） | 4 | 内部队列 | 参考脚本 `alps.sh` 加参数对齐补丁：`-d 3 -e eddy_cuda11.0 -r 2.5 -t 1 -f 2`，配准代价 patch 为 `normmi`；ALPSbox 侧用默认值 |
| 参考实现对比（完全外部队列） | 30 | ds000030 | 参考实现同上参数对齐设置 |
| 配准路径对比（配对） | 10 | 内部队列 | 直接 FA→模板路径 vs 两步复合变换，其余默认 |
| 配准矩阵敏感性（`--regqc`） | 24 | 内部队列 | 对配准矩阵做 12 次 ±0.5° / ±0.5 mm 扰动 |
| 脑提取阈值（`bet -f`）0.5 vs 0.3 | 24 | 内部队列 | 只改 `bet -f` |
| 脑提取阈值外部复现 | 15 | ds000030 | 只改 `bet -f`；按 `r_wm` 分组；以头动为协变量 |
| 配准代价 `normmi` vs `corratio` | 5 | 外部（ds000030） | 只改 FLIRT 代价函数 |
| eddy 非确定性 | 3 | 内部队列 | 同一输入重复跑 `eddy_cuda` |
| 真实 PA/AP 数据上的 TOPUP | 1 | 内部队列 | 加反相位编码第二套 DWI；TOPUP 开/关对比 |

**数据可得性**：外部队列为公开的 OpenNeuro `ds000030`（CC0；引用见
[CITATIONS.md](CITATIONS.md) §7）。内部队列因隐私原因不再分发；汇总结果与每个
实验的参数均已列于上表，完整记录可向作者索取。

## 6. 适用范围与局限

- 验证队列均为单中心、3T、单壳（b = 1000）：内部 1.5 mm，外部 1.98 mm。
  未经重新验证时，ALPS 数值不可跨采集协议直接比较。
- 跨实现对比时，参考实现使用了参数对齐补丁；其默认设置不同
  （`-f 1`、去噪+去振铃、corratio）。详见 [CITATIONS.md](CITATIONS.md) §2.1。
- 组水平统计被刻意排除在工具之外；验证只使用每个被试的数值。
- TOPUP 对比只有 1 例，只说明方向与大致量级，不是可外推的估计。
- 参考实现自己的 README 指出，其默认 `eddy_cpu` 路径的运行间变异大于本工具使用的
  GPU 路径；因此小差异阈值必须谨慎解释。
